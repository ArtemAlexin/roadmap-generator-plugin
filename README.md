# Roadmap Generator Plugin

Переносимый локальный плагин для агента: интерактивный опрос → содержательная программа → отдельный проверяющий → офлайн HTML, PDF или оба формата. Основан на пользовательском `roadmap_universal_html_pdf_v7.txt`. Пример Agentic SE Roadmap использован как ориентир структуры и UX; его учебное содержание и код не копировались.

Модель создаёт и проверяет учебное содержание. Готовый код хранит состояние, проверяет структуру и собирает файлы. API-ключей и отдельных платных вызовов моделей нет. Независимого проверяющего запускает агент-хост или пользователь в другой сессии.

## Версия 0.0.7: установка из GitHub

### OpenCode 2.2.5

```powershell
opencode plugin add "github:ArtemAlexin/roadmap-generator-plugin#0.0.7"
```

Перезапустите OpenCode и введите в чате `/roadmap Ваша цель`. OpenCode устанавливает Git-пакет и его npm-зависимости. Нужен Node.js 22+; для HTML QA/PDF — установленный Edge/Chrome либо Chromium. Глобальную запись с локальным file:// путём следует заменить Git-версией, чтобы не подключать две копии одного плагина.

### Codex: локальная установка

Скачайте текущий репозиторий (через Git или ZIP) и запустите локальный установщик. Нужны Node.js 22+, npm и актуальный Codex CLI с командой `codex plugin add`. Команды для PowerShell:

```powershell
git clone --branch 0.0.7 https://github.com/ArtemAlexin/roadmap-generator-plugin.git
cd roadmap-generator-plugin
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-codex.ps1
```

Для Linux/macOS используйте `sh`:

```sh
git clone --branch 0.0.7 https://github.com/ArtemAlexin/roadmap-generator-plugin.git
cd roadmap-generator-plugin
sh scripts/install-codex.sh
```

Если скачали ZIP, распакуйте его и выполните последнюю команду из папки с `package.json`. Установщик добавляет локальный каталог `roadmap-tools`, устанавливает плагин `roadmap-generator`, получает от Codex фактический путь установленной копии и выполняет `npm ci --omit=dev` именно в ней. Затем проверяет MCP handshake, список инструментов и чтение workflow. Для HTML/PDF проверяет запуск браузера; если доступного Edge/Chrome/Chromium нет, устанавливает Chromium. При первой установке нужен доступ к npm registry и, при загрузке браузера, к серверам Playwright. `npm ci` в исходном клоне перед запуском установщика не требуется.

Перезапустите Codex и откройте новый чат. Плагин предоставляет навык `roadmap` и MCP-инструменты. Проверка в чате:

> Используй навык roadmap. Сначала вызови roadmap_guidance с phase=workflow, затем помоги создать учебную программу.

Если ранее добавляли отдельный MCP-сервер командой `codex mcp add roadmap`, удалите эту отдельную запись через `codex mcp remove roadmap`, чтобы не подключать сервер дважды. Сам плагин оставьте включённым.

При обновлении локального репозитория повторите запуск установщика и перезапустите Codex. Не редактируйте кэш плагинов вручную. Параметр `-SkipBrowser` (PowerShell) или `--skip-browser` (`sh`) пропускает проверку и установку браузера; тогда HTML QA/PDF потребуют доступного браузера позднее. В Linux для Chromium также могут понадобиться системные библиотеки Playwright; установите их через пакетный менеджер своей ОС, если проверка браузера сообщает об их отсутствии. Не используйте старый тег `0.0.3` для получения установщика: он добавлен после этого тега.

Это собственный Git-каталог, а не публикация в общем публичном каталоге OpenAI. В опубликованном Git-пакете сохранён `private: true`: релиз распространяется из GitHub, в npm registry он не публикуется.

## Установка зависимостей

Нужны Node.js 22+ и npm. Из каталога проекта:

```powershell
npm ci
npx playwright install chromium
```

Если уже установлен Edge или Chrome, отдельный Chromium необязателен: сборщик попробует их автоматически. Можно указать `ROADMAP_BROWSER_PATH` — абсолютный путь к браузеру. Браузер нужен также для технической проверки HTML.

## Подключение к любому локальному MCP-агенту

Выполните:

```powershell
node src/cli.js config
```

Команда выведет готовый JSON `mcpServers` с абсолютными путями для текущего расположения проекта. Добавьте его в конфигурацию клиента, поддерживающего **локальный MCP stdio**. У некоторых клиентов корневой ключ называется `servers`; перенесите внутреннюю запись в их формат. Не запускайте `npm start` отдельным фоновым процессом: MCP-клиент сам запускает сервер и общается с ним через stdin/stdout.

После подключения попросите агента:

> Используй MCP roadmap. Сначала вызови roadmap_guidance с phase=workflow. Создай для меня roadmap, задавай вопросы по одному, затем дай выбрать HTML, PDF или оба формата и папку сохранения.

Если клиент поддерживает MCP prompts, доступен `create-roadmap`. Если поддерживает навыки, загрузите `skills/roadmap/SKILL.md`. Только обнаружение инструментов не гарантирует, что произвольный агент сам выберет весь процесс: используйте prompt/skill или приведённую вводную команду.

Клиент с MCP elicitation получает последовательность форм **по одному вопросу**: один вызов `roadmap_question` интерактивно собирает все оставшиеся ответы до завершения или отмены. После отмены продолжение снова использует формы. Если MCP elicitation нет, агент обязан использовать собственный интерактивный инструмент вопросов для **каждого** вопроса, сохраняя ответ и снова вызывая `roadmap_question`. Обычный чат допустим только при отсутствии у хоста любого интерактивного ввода, с явным объяснением ограничения. Свободный ввод доступен для цели, уровня, срока, ограничений, приоритетов и пути. Формат выбирается как «Интерактивный локальный сайт (ZIP)», «PDF-документ» или «Интерактивный сайт (ZIP) и PDF». Внутренние значения html/pdf/both сохраняются для совместимости; html всегда означает многостраничный интерактивный сайт, а не один HTML-файл.

Поддержка ограничена агентами с локальным выполнением и MCP stdio. Чисто облачным агентам без локального исполнителя понадобится отдельный HTTP-адаптер/развёртывание; в этой версии его нет. Варианты пользовательского UI, разрешений и запуска субагентов определяются клиентом.

## Codex: альтернативное подключение только через MCP

Нужны Git, Node.js 22+, npm и установленный Codex CLI. Выполняйте команды в PowerShell. Если репозиторий уже клонирован, перейдите в его папку и пропустите `git clone`.

```powershell
git clone --branch 0.0.7 https://github.com/ArtemAlexin/roadmap-generator-plugin.git
cd roadmap-generator-plugin
npm ci

# Абсолютные пути сохранятся в конфигурации Codex.
$roadmapRoot = (Get-Location).Path
$roadmapNode = (Get-Command node -CommandType Application).Source
codex mcp add roadmap -- "$roadmapNode" "$roadmapRoot\src\server.js"
codex mcp get roadmap
codex mcp list
```

Этот способ нужен для отдельного MCP-сервера без установки плагина. Если Roadmap Generator уже установлен через установщик выше, используйте его либо отключите плагин перед прямым подключением, чтобы избежать двойного подключения. Прямое MCP-подключение регистрирует инструменты и prompt сервера; оно само по себе не устанавливает навык плагина или команду `/roadmap`.

Для HTML QA и PDF нужен браузер. При установленном Edge или Chrome отдельная установка не требуется. Иначе из папки репозитория выполните:

```powershell
npx playwright install chromium
```

Для длительной сборки добавьте `tool_timeout_sec = 300` в существующую секцию `[mcp_servers.roadmap]` файла `%USERPROFILE%\.codex\config.toml`. Не создавайте вторую секцию с тем же именем.

Перезапустите Codex и откройте новый чат. `codex mcp list` проверяет наличие записи в конфигурации; работоспособность проверьте в чате:

> Вызови MCP roadmap_guidance с phase=workflow и подтверди, что инструкция прочитана.

Затем используйте вводную команду из раздела выше. Сервер запускает сам Codex; отдельно выполнять `npm start` не нужно. Синтаксис подключения описан в [официальной документации MCP](https://learn.chatgpt.com/docs/extend/mcp).

Не перемещайте и не удаляйте локальный клон: Codex запускает сервер из него. После обновления кода выполните `npm ci` в этой же папке и перезапустите Codex. Если путь изменился, удалите старую запись командой `codex mcp remove roadmap` и повторите подключение с новым абсолютным путём. При `ERR_MODULE_NOT_FOUND` проверьте путь через `codex mcp get roadmap` и установите зависимости именно в указанном клоне.

## OpenCode: нативный плагин

В проекте есть нативный адаптер OpenCode V2: `integrations/opencode/index.js`, объявленный основным экспортом npm-пакета. Он регистрирует MCP-сервер, навык `roadmap` и команду `/roadmap`. Отдельные записи `mcp`/`skills` для этого способа не нужны. Настройки других серверов, модели и разрешений адаптер не меняет.

**Быстрый запуск:** в корне уже есть `opencode.json` с автоподключением этого плагина. Откройте проект в OpenCode:

```powershell
opencode "C:\path\to\roadmap-generator-plugin"
```

Затем в чате введите `/roadmap Ваша цель`. Следующие шаги нужны только для подключения из других рабочих проектов.

Из каталога проекта выполните:

```powershell
node src/cli.js config opencode
```

Для установленного OpenCode 2.2.5 команда выдаёт:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    "file:///C:/path/to/roadmap-generator-plugin/"
  ]
}
```

Добавьте запись в `opencode.json` или `opencode.jsonc` того проекта, где используете OpenCode. Существующую конфигурацию сохраняйте, путь добавляйте к имеющемуся массиву. Для подключения во всех проектах используйте пользовательский конфиг OpenCode. В OpenCode 2.2.5 работает ключ **`plugin`**, тогда как актуальная документация описывает более новый **`plugins`**; для такого формата выполните `node src/cli.js config opencode --modern`.

Перезапустите OpenCode (либо перезагрузите конфигурацию) и проверьте:

```powershell
opencode plugin list
opencode mcp list
```

В чате запустите:

```text
/roadmap Хочу научиться [ваша цель]
```

Или напишите: «Используй навык roadmap и создай программу для …». Команда сохраняет исходный запрос, вложения и выбранную сессию. Генератор задаёт вопросы по одному, затем спрашивает формат и каталог сохранения. Отдельный проверяющий остаётся обязанностью агента-хоста.

Не подключайте одновременно вторую копию того же MCP-сервера вручную. Если запись `roadmap` уже указывает на тот же сервер, адаптер сохраняет её настройки, включая явное отключение. При конфликте с другим сервером он сообщает об ошибке. Для адаптации имени/Node/каталога состояния в версиях OpenCode с объектными опциями плагинов доступны `serverName`, `commandName`, `nodeCommand`, `dataDirectory`; в 2.2.5 используйте строковую запись и переменные `ROADMAP_NODE_PATH`, `ROADMAP_DATA_DIR`.

OpenCode V1 нативным адаптером не поддерживается. Для V1 остаётся прямое MCP-подключение по формату соответствующей версии. Реальный smoke-тест V2 без вызовов моделей:

```powershell
npm run test:opencode
```

Нужен установленный OpenCode. На Windows тест ищет стандартную npm-установку; для другого расположения задайте `OPENCODE_EXECUTABLE` абсолютным путём к исполняемому файлу. Тест создаёт изолированные конфигурацию, данные и localhost-сервер, проверяет реестры плагинов/навыков/команд/MCP и завершает созданные процессы. Пользовательский конфиг не изменяется. `OPENCODE_CONFIG_STYLE=modern` переключает тест на новый ключ `plugins`.

Документация API: [плагины](https://opencode.ai/docs/build/plugins/server), [конфигурация](https://opencode.ai/docs/plugins/). При расхождении документации и установленного релиза используйте проверенный для релиза формат.

## Установка как пакет плагина

В корне находятся portable `plugin.json` и `mcp.json`, навык `skills/roadmap`, а также совместимый `.codex-plugin/plugin.json` и `.mcp.json`. Portable-пакет использует `${PLUGIN_ROOT}`, совместимый MCP-файл — `${CLAUDE_PLUGIN_ROOT}`. Клиент должен поддерживать соответствующую подстановку. Для других клиентов надёжнее получить абсолютный конфиг командой `node src/cli.js config`.

Для Codex-плагина в проекте есть локальный каталог `.agents/plugins/marketplace.json`. Добавьте источник:

```powershell
codex plugin marketplace add "C:\path\to\roadmap-generator-plugin"
```

Затем откройте каталог плагинов приложения, выберите источник Roadmap Tools и установите Roadmap Generator. Зависимости должны быть установлены в используемой копии пакета. Не подключайте один сервер одновременно через ручной MCP-конфиг и плагин, чтобы избежать двух одинаковых наборов инструментов.

Формат пакета описан в [документации OpenAI](https://developers.openai.com/plugins/build/plugins). Установка через каталог Codex не выполнялась; MCP-протокол проверен тестовым клиентом, а нативная активация OpenCode 2.2.5 — отдельно на установленном приложении в изолированном окружении. В этой версии нет публикации в публичном каталоге.

## Использование и продолжение

Опрос запрашивает цель, уровень и режим планирования. **Свободный график**: часы в неделю и дедлайн не спрашиваются; этапы и вся программа оцениваются в часах, порядок задаётся зависимостями и DoD, календарная длительность не рассчитывается. **План по часам в неделю**: дополнительно запрашиваются недельный бюджет и желаемый срок (можно без дедлайна). Далее — ограничения, приоритеты/исключения, формат и каталог. Уже переданные факты пропускаются. Числовой недельный бюджет в старой сессии сохраняет прежний режим; явный выбор свободного графика отменяет его использование для календарных расчётов. Пользовательский DoD принимается как необязательное исходное поле; если его нет, агент выводит критерии из цели.

Сохраняйте `sessionId`: по нему продолжается работа после перезапуска через `roadmap_get`. По умолчанию состояние хранится вне пакета: на Windows `%LOCALAPPDATA%\roadmap-generator\state`, при наличии `PLUGIN_DATA` — внутри каталога данных плагина. Изменить можно переменной `ROADMAP_DATA_DIR` или аргументом сервера `--data-dir`. Один каталог сессий обслуживайте одним процессом сервера; параллельные вызовы внутри него сериализуются.

Папку результата выбирает пользователь в опросе. Сборщик сначала формирует выбранные форматы во временном staging и выполняет машинные проверки HTML, ZIP и/или PDF, затем копирует файлы без перезаписи в отдельную папку с безопасным читаемым именем из заголовка (или цели), UTC-даты и случайного суффикса:

```text
<безопасный-заголовок>-<YYYY-MM-DD>-<8-hex>/
  index.html            # Открыть в браузере при выборе HTML
  about.html
  report.html
  assets/
  stages/
  roadmap.pdf           # При выборе PDF
<безопасный-заголовок>-<YYYY-MM-DD>-<8-hex>-html.zip  # Архив сайта рядом с каталогом, при выборе HTML
```

В режиме PDF в каталоге результата находится только `roadmap.pdf`. Служебные `roadmap.json`, `manifest.json` и снимки `qa/` сохраняются отдельно в каталоге данных плагина `builds/<build-UUID>/`. Фактические пути доступны в `diagnostics` результата `roadmap_build`; пользовательский каталог сайта содержит только файлы сайта и выбранный PDF. Destination, diagnostics и системный TEMP не должны пересекаться вложенными путями; конфликт отклоняется до записи файлов сборки. Машинные проверки не заменяют просмотр снимков и страниц PDF: `visualReview` остаётся pending до проверки хостом. Каталог и соседний ZIP не образуют атомарную транзакцию, поэтому аварийное завершение может оставить частичные файлы.

HTML работает по file:// без CDN и сервера; интернет нужен для внешних учебных материалов. Поиск, DAG, масштабирование, темы, отметки этапов/DoD и импорт/экспорт прогресса работают локально. Отметки не меняют оценку программы. Хранение localStorage по file:// зависит от браузера; при его недоступности приложение продолжает работать.

## Независимая проверка

`roadmap_prepare_review` создаёт пакет без прежней рецензии, самооценки и журнала изменений. Его нужно дать другому экземпляру модели в чистом контексте. Проверяющий читает схему `roadmap_schema(review)` и возвращает фактически выполненные проверки, выборку, замечания и уровни подкритериев. Автор отправляет результат в `roadmap_submit_review` с ID запроса.

Весовая рубрика сохранена: максимум 100, порог 85, исходные блокирующие условия. Сервер вычисляет баллы, проверяет доступные структурные ограничения и привязывает рецензию к хешу содержания и входных данных. Изменения делают рецензию устаревшей. Максимум — начальная оценка и три цикла доработки.

**Сервер не способен доказать независимость модели или истинность записанного аудита источников.** Это обязанность агента-хоста; `identity` и `independent` — явные заявления. Веб-поиск и чтение источников выполняются инструментами агента. Поля `verified` нельзя заполнять по одному названию/сниппету. Если нет актуальной проходной независимой оценки, результат выпускается с заметной маркировкой «Предварительная программа». Структурно повреждённые данные экспорт не проходят.

## Тесты и демонстрация

```powershell
npm test
npm run test:ui
npm run test:all
npm run demo
```

Модульные и интеграционные тесты: граф, ссылки между объектами, часы, рубрика, блокирующие условия, сохранение/продолжение, очистка пакета проверки, устаревшая рецензия, XSS и настоящий MCP stdio round-trip, включая elicitation.

Playwright: file://, переходы и семь блоков этапа, поиск с клавиатуры, темы, прогресс, импорт, localStorage fallback, карта, адаптивность на 360/390/1440 px, обе темы и axe-проверки доступности. Это автоматические проверки, не сертификат полной WCAG-совместимости любого будущего содержания.

Демонстрация использует **синтетическую** программу. Её статусы источников — фикстуры программных тестов, не заявления о реальном исследовании. Демонстрация маркирована предварительной. Сборка сохраняет восемь снимков; агент должен их посмотреть, прежде чем объявлять визуальную проверку завершённой. PDF требует отдельного просмотра отрендеренных страниц.

При ограничениях sandbox браузеру может требоваться разрешение на запуск. Если временный каталог sandbox запрещает rename, задайте TEMP/TMP на разрешённую рабочую папку. Не отключайте проверки, чтобы получить зелёный результат.

## Устройство проекта

- `src/schema.js`, `schema/roadmap.schema.json`: формат данных.
- `src/store.js`, `src/questions.js`: состояние и последовательный опрос.
- `src/validate.js`: механическая проверка и расчёт рубрики.
- `src/render.js`, `assets/`: общие HTML/PDF-представления.
- `src/build.js`: сборка, ZIP и техническая проверка.
- `src/server.js`: MCP tools и prompt.
- `src/cli.js`: конфиг, опрос в терминале, валидация, импорт и сборка.
- `skills/roadmap/`: инструкции по стадиям, исходная рубрика и требования к обучению.
- `docs/original-prompt-v7.txt`: неизменённый исходный промпт для сверки.

Правила интерпретации противоречий исходного промпта и учёта времени находятся в `skills/roadmap/references/data.md`. Рубрика не меняется ради интерфейса. Для изменения данных используйте небольшие upsert-операции; заново генерировать код при каждом roadmap не требуется.
